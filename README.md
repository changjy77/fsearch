# 🔍 fsearch - Windows 파일 검색 도구

![Version](https://img.shields.io/badge/version-1.4.0-blue)
![License](https://img.shields.io/badge/license-MIT-green)
![Python](https://img.shields.io/badge/python-3.12-blue)
![Platform](https://img.shields.io/badge/platform-Windows-blue)

**빠르고 강력한 Windows 파일 검색 프로그램**

파일명과 파일 내용을 동시에 빠르게 검색하고, 원클릭으로 파일을 실행할 수 있는 PyQt5 기반의 데스크톱 애플리케이션입니다.

---

## ✨ 주요 기능

### 🔍 고급 검색
| 기능 | 설명 |
|------|------|
| **파일명 검색** | 빠른 파일명 검색 |
| **내용 검색** | 파일 내용에서 검색어 찾기 |
| **정규식** | 복잡한 패턴 검색 (예: `.*\.(doc\|docx)`) |
| **실시간 검색** | 검색 중 실시간 결과 표시 |
| **검색 제어** | 언제든지 검색 중단 가능 |

### ⚡ 성능 최적화
- **전문검색 인덱스**: 캐시된 본문을 SQLite FTS5(trigram)로 색인해, 매 검색마다 캐시 전체를 메모리로 올리지 않고 키워드를 포함한 파일만 조회 (캐시 로드 1.62초 → 0.17초). trigram 방식이라 "네이버"로 "네이버클라우드"를 찾는 부분 문자열 검색이 그대로 동작
- **프로세스 병렬 추출**: 문서 파싱은 GIL 때문에 스레드로는 병렬화되지 않아(16스레드로도 1.03배) ProcessPoolExecutor로 분리. 대상이 적을 때는 프로세스 생성 비용이 더 커서 스레드로 처리
- **멀티스레드 검색**: 기본 16개 스레드 (1~32 조정 가능)
- **디스크 캐싱**: 추출한 텍스트를 SQLite(`~/.fsearch/text_cache.db`)에 저장해, 같은 폴더를 다른 검색어로 재검색할 때 파싱을 건너뛰고 재사용
- **zip 내부 캐싱**: 압축파일 내부 파일은 CRC+크기 기준으로 변경 감지 — zip 안의 파일 하나만 바뀌어도 그 파일만 재추출
- **매칭 로직 최적화**: 정규식 엔진의 대소문자무시 매칭으로 전체 텍스트를 먼저 확인해, 매칭이 없으면 줄 단위 분리/소문자 변환을 생략
- **파일명 전용 검색 가속**: "파일명만" 검색 시 불필요한 텍스트 캐시 로드를 생략해 체감 속도 대폭 향상
- **대용량 파일 스킵**: 10MB 이상 자동 제외 (선택)

### 📂 폴더 관리
- **폴더 제외**: 검색에서 제외할 폴더 설정 (AppData, Program Files 등)
- **최근 경로**: 자주 검색하는 경로 저장 (최대 5개)
- **제외 통계**: 자주 제외하는 폴더를 자동 기록해 상위 3개를 노출

### 📊 검색 결과
| 컬럼 | 내용 |
|------|------|
| **파일명** | 윈도우 탐색기와 동일한 파일 아이콘 + 검색어 붉은색 강조 표시 |
| **경로** | 전체 파일 경로 |
| **크기** | B, KB, MB 단위 자동 변환 |
| **수정 날짜** | 마지막 수정 날짜/시간 |
| **검색 단어수** | 파일 내 검색어 출현 횟수 |

- **업무 연관도 정렬**: 단순 매칭 횟수가 아니라 휴리스틱 점수(파일명 일치, 문서 형식 가중치, 소스코드 감점 등)로 정렬
- **행 호버 강조**: 마우스를 올린 행이 진한 회색으로 표시
- **호버 미리보기**: 매칭된 라인 최대 4줄을 툴팁으로 표시, 파일명에만 검색어가 있으면 "본문에 검색어 없음"으로 별도 안내

### 📁 지원 파일 형식
- **문서**: Word (.docx), PowerPoint (.pptx), PDF (.pdf)
- **텍스트**: 텍스트 (.txt), 마크다운 (.md), HTML (.html, .htm)
- **한글**: 한글 (.hwpx), 구버전 한글 (.hwp)
- **스프레드시트**: Excel (.xls, .xlsx)
- **데이터**: CSV (.csv), JSON (.json), XML (.xml)
- **압축파일**: ZIP (.zip) — 내부 문서까지 풀어서 검색
- **파일명만 검색**: 구버전 Word (.doc), 구버전 PowerPoint (.ppt) — 본문 추출을 지원하지 않아 "내용만" 옵션과 무관하게 파일명으로만 매칭

> **.hwp 참고**: 구버전 한글 파일은 문서에 포함된 미리보기 텍스트(PrvText)에서 본문을 추출합니다.
> 문서 전체가 아니라 미리보기 범위까지만 검색되므로, 뒷부분에만 있는 단어는 찾지 못할 수 있습니다.
> .hwpx는 본문 전체를 검색합니다.

### 🚀 편의 기능
- **빠른 실행**: 결과 더블클릭으로 파일/폴더 열기
- **엑셀로 내보내기**: 결과 테이블 내용(파일명/경로/크기/수정 날짜/검색 단어수)을 xlsx 파일로 저장
- **검색 이력**: 최근 검색 키워드 10개, 검색 경로 5개 저장 (각각 초기화 버튼 제공)
- **창 크기 대응**: 검색 옵션/버튼 줄이 창 너비에 맞춰 자동으로 줄바꿈
- **성능 측정**: 검색 소요 시간 표시
- **자동 로깅**: 홈 디렉토리의 `.fsearch/logs` 폴더에 저장
- **대용량파일 로그**: 스킵된 파일 목록 확인 가능

## 📥 설치 및 사용

### 🎯 방법 1: 실행 파일 (권장 - 가장 간단함)

**단계별 설치:**
1. `dist/fsearch.exe` 다운로드
2. 원하는 폴더에 저장
3. 더블클릭으로 실행

**장점:**
- Python 설치 불필요
- 바로 사용 가능
- 어디서나 실행 가능

### 💻 방법 2: 소스코드 실행 (개발자용, Windows/macOS/Linux 공통)

**설치 (Windows):**
```bash
# 1. 저장소 복제
git clone https://github.com/changjy77/fsearch.git
cd fsearch

# 2. 필수 라이브러리 설치
pip install -r requirements.txt

# 3. 실행
python fsearch_gui.py
```

**설치 (macOS):**
```bash
# 1. 저장소 복제
git clone https://github.com/changjy77/fsearch.git
cd fsearch

# 2. 필수 라이브러리 설치 (Python 3.9+ 권장, python3/pip3 사용)
pip3 install -r requirements.txt

# 3. 실행
python3 fsearch_gui.py
```

**장점:**
- 소스코드 수정 가능
- 최신 버전 사용
- 커스터마이징 가능

> **참고**: `dist/fsearch.exe`는 Windows 전용 배포 파일입니다. macOS/Linux는 위처럼 소스코드로 직접 실행하며,
> 파일 실행(더블클릭 상당 기능)은 `os.startfile`(Windows) / `open`(macOS) / `xdg-open`(Linux)으로 자동 분기됩니다.
> macOS에서의 실제 동작은 제작 환경(Windows)에서 직접 검증하지 못했으니, 실행 중 문제가 있으면 알려주세요.

> **SQLite 요구사항**: 본문 검색 인덱스가 FTS5 trigram 토크나이저를 사용하므로 **SQLite 3.34 이상**이 필요합니다.
> 버전 확인: `python -c "import sqlite3; print(sqlite3.sqlite_version)"`
> Windows용 공식 Python과 최신 배포판에는 충분히 최신 버전이 포함되어 있습니다.

## 🎯 사용 방법

### 기본 사용 예시

```
1️⃣ 검색 폴더 선택
   - 경로 입력칸은 기본적으로 비어 있음 — 직접 입력하거나 "찾아보기" 버튼으로 지정
   - 최근 사용한 경로는 드롭다운 목록에서 선택 가능

2️⃣ 검색어 입력
   - 파일명 검색: "report"
   - 내용 검색: 파일 내에 포함된 텍스트

3️⃣ 검색 옵션 선택 (필요시)
   - "파일명만": 파일명에서만 검색
   - "내용만": 파일 내용에서만 검색
   - "정규식": 정규표현식 사용
   - "대용량파일 스킵": 10MB+ 파일 제외

4️⃣ "🔍 검색" 버튼 클릭
   - 진행 상태는 진행바로 확인
   - 검색 중단: "⏹️ 중지" 버튼

5️⃣ 결과 확인
   - 테이블 탭: 구조화된 결과 표시
   - 텍스트 탭: 상세 정보 표시
   - 파일 더블클릭으로 즉시 열기
```

**예제 1: Word 문서에서 "회의록" 검색**


## ⚙️ 시스템 요구사항

| 항목 | 최소사양 | 권장사양 |
|------|---------|---------|
| **OS** | Windows 7 | Windows 10+ |
| **메모리** | 512MB | 4GB+ |
| **디스크** | 100MB (프로그램) | 프로그램 100MB + 캐시 여유 공간 |
| **프로세서** | Intel Core i5 | Intel Core i7+ |

> **캐시 디스크 사용량**: 검색한 문서의 본문과 FTS5 인덱스가 `~/.fsearch/text_cache.db`에 쌓입니다.
> 본문 1GB(문서 약 4만 건)를 캐싱한 환경에서 인덱스 포함 약 3GB를 사용했습니다.
> 용량이 부담되면 이 파일을 삭제하면 되며(다음 검색 시 다시 만들어짐), 검색 결과에는 영향이 없습니다.

## 🔧 개발 정보

### 기술 스택
- **언어**: Python 3.12
- **GUI**: PyQt5 (5.15.9+)
- **병렬 처리**: ProcessPoolExecutor (텍스트 추출, GIL 우회) + ThreadPoolExecutor (검색, 기본 16개)
- **캐싱**: sqlite3 (텍스트 추출 결과 디스크 캐싱 + FTS5 trigram 전문검색 인덱스)
- **파일 처리**:
  - python-docx (Word 문서, 파싱 실패 시 zip 내부 XML 직접 추출로 우회)
  - python-pptx (PowerPoint 문서)
  - PyMuPDF (PDF)
  - openpyxl / xlrd (Excel .xlsx / .xls)
  - olefile (한글 .hwp, PrvText 스트림에서 추출)
  - zipfile / xml.etree.ElementTree (한글 .hwpx, .zip 내부 검색)

### 프로젝트 구조
```
fsearch/
├── fsearch_gui.py          # 메인 프로그램 (~2,740줄)
├── fsearch.spec            # PyInstaller 빌드 설정
├── requirements.txt        # 의존 라이브러리
├── README.md               # 사용 설명서
├── .gitignore              # Git 무시 파일
└── dist/
    └── fsearch.exe         # 배포용 실행 파일 (약 69MB)
```

### 주요 클래스
- **SearchWorker**: QThread 기반 검색 엔진 (프로세스풀 추출 + 스레드풀 검색)
- **SearchHistory**: 검색 이력 및 설정 관리
- **TextExtractionCache**: SQLite 텍스트 캐시 및 FTS5 trigram 인덱스 관리
- **HoverableTableWidget**: 행 호버 강조를 지원하는 테이블 위젯
- **SearchResultDelegate**: 결과 행 렌더링(검색어 강조 등) 담당
- **FlowLayout**: 창 너비에 따라 위젯을 자동 줄바꿈하는 레이아웃
- **FSearchGUI**: 메인 UI 윈도우

### 핵심 기능
- **검색 엔진**: 문서 파싱은 ProcessPoolExecutor(GIL 우회), 파일 순회/매칭은 ThreadPoolExecutor로 처리
- **본문 검색**: SQLite FTS5 trigram 인덱스로 캐시된 본문을 조회. 정규식 모드, 3글자 미만 키워드, 비ASCII 대소문자가 섞인 키워드는 인덱스 결과가 파이썬 매칭과 달라질 수 있어 전체 스캔 경로로 폴백
- **파일 처리**: 15개 확장자 + zip 내부 검색 지원 (Word, PowerPoint, PDF, Excel, 한글, CSV/JSON/XML 등)
- **디스크 캐싱**: 재검색 시 텍스트 추출을 건너뛰어 속도 향상
- **UI/UX**: PyQt5 탭 인터페이스 (테이블/텍스트 결과), 행 호버 강조, 윈도우 탐색기 아이콘 표시
- **검색 결과 강조 및 정렬**: 검색어 붉은색 표시, 업무 연관도 기반 정렬
- **파일 실행**: 검색 중/완료 상관없이 더블클릭으로 즉시 실행

## 🐛 트러블슈팅

### Q: 파일이 실행되지 않습니다
**A**: 다음을 확인하세요:
- fsearch.exe가 손상되지 않았는지 확인
- Windows Defender에서 차단되지 않았는지 확인
- 관리자 권한으로 실행 시도
- 파일이 실제로 존재하는지 확인 (네트워크 경로는 지원 불가)

### Q: 검색이 느립니다
**A**: 다음을 시도하세요:
- 대용량파일 스킵 체크 활성화
- 스레드 수 증가 (기본 16 → 32)
- 검색 폴더 범위 축소
- 불필요한 폴더 제외 (AppData, Temp 등)

처음 검색하는 폴더는 문서를 파싱해야 해서 느리고, 두 번째 검색부터 캐시가 적용되어 빨라집니다.
정규식 모드와 3글자 미만 키워드는 전문검색 인덱스를 쓸 수 없어 일반 검색보다 느립니다.

### Q: v1.4.0으로 올린 뒤 첫 검색이 유난히 오래 걸립니다
**A**: 정상입니다. 기존 캐시를 전문검색 인덱스로 색인하는 1회성 작업으로,
문서 4만여 건 기준 약 2분이 걸립니다. 완료 후에는 다시 실행되지 않습니다.

### Q: `~/.fsearch/text_cache.db` 파일이 너무 큽니다
**A**: 검색한 문서의 본문과 검색 인덱스가 누적된 파일입니다. 삭제해도 검색 결과에는 영향이 없으며,
다음 검색 시 필요한 만큼 다시 만들어집니다 (그만큼 첫 검색이 느려집니다).

### Q: 특정 파일 형식이 검색되지 않습니다
**A**: 지원 형식 확인:
- 문서: .doc(파일명만), .docx, .ppt(파일명만), .pptx, .pdf, .txt, .md
- 스프레드시트: .xls, .xlsx
- 한글: .hwp, .hwpx
- 웹: .html, .htm
- 데이터: .csv, .json, .xml
- 압축파일: .zip (내부 문서까지 검색)

### Q: 로그 파일은 어디에 있나요?
**A**: `C:\Users\<username>\.fsearch\logs\` 폴더 확인

### Q: 검색 중에 파일을 실행할 수 있나요?
**A**: ✅ 가능합니다! 검색이 진행 중일 때도 테이블에서 파일을 더블클릭하면 즉시 실행됩니다.
